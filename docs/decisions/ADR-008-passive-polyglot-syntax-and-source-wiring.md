# ADR-008 — Automatic passive syntax and open-context source wiring

Date: 2026-11-04. **PROVISIONAL implementation choice under confirmed human authorization** to address all five scan findings, use online evidence acquisition and maximize coverage while retaining execution safety. Authored regression evidence is recorded in `docs/current-state.md`; this decision does not close M8.4 or certify arbitrary repositories.

Ordinary scan must produce useful evidence without requiring an operator-authored native publication first. Inventory alone does not capture program structure. Requiring every compiler/SDK before acquiring any structure also discards useful facts when a toolchain is unavailable. Conversely, a syntax tree does not establish overload resolution, dispatch, active routes or runtime DI.

Add `analyzer-treesitter`, depending inward on the analyzer domain, using the pinned Java-21-compatible [Tree-sitter NG binding](https://github.com/bonede/tree-sitter-ng). Its bundled grammars parse captured bytes as data; target build logic, interpreters, compiler hooks, libraries and project-selected grammars never execute. The [Tree-sitter parser model](https://github.com/tree-sitter/tree-sitter) supplies concrete syntax; native compiler/typechecker providers remain the stronger binding path. This complements the existing 18 language adapters and preserves JavaParser for Java.

The initial passive pack contains 16 grammar artifacts for 15 non-Java languages, including TSX as a TypeScript dialect. Exact versions are in `analyzer-treesitter/pom.xml`; actual native core/grammar, binding and extractor bytes contribute SHA-256 identities. Source bytes, full positions, written names, parser recovery and lexical owners accompany facts. Call-site membership and route literal candidates use `syntax.*` graph relations; they never become verified `java.calls` or active `ENDPOINT` facts. Interpolated/dynamic route expressions are not normalized into literal paths. Groovy and Visual Basic retain native-provider requirements; they are not silently omitted or described as supported by this passive pack.

Parse one file at a time and spool sorted neutral records through SQLite/CAS. The per-file resource policy is recorded. Unsupported encoding/grammar, malformed source, unavailable bytes and worker requirements retain document outcomes and typed gaps. If the legacy Java compatibility view needs another worker, publish the complete inventory and available syntax/native facts under their real inventory snapshot, with an explicit Java obligation. Do not fabricate an empty legacy Java snapshot or discard unrelated languages.

Spring enrichment separately acquires source type candidates from evidenced component declarations, composed source annotations, bean-method return types, constructor/field sites, Lombok candidate fields and positively identified Spring Data repository interfaces. Meta-annotation closure requires an evidenced root and terminates on cycles. Known type paths create possible source-wiring edges. Activation, qualifier/generic compatibility and final selection remain unknown/not evaluated. The existing configuration/registration/truth engine remains responsible for selected bindings. This follows the distinction between type candidates and [Spring autowire selection](https://docs.spring.io/spring-framework/reference/core/beans/dependencies/factory-autowire.html), rather than treating an open classpath as an empty container.

Only frontends explicitly declaring independent per-request state can overlap. Admit tasks by CPU, estimated AST plus JDK/JAR cost and current heap headroom, allowing an oversized unit to proceed alone; merge in source order. Retain completed-context reservations until a drained boundary releases parser caches. JavaParser uses an adapter-owned read/write lifecycle around its shared facade cache: clear only when resolution is idle, including direct/serial calls. Scheduling cannot change semantic identities or turn worker exhaustion into a repository-size exclusion. Index annotation, constructor-parameter and declaration lookups once instead of repeatedly scanning full populations. Replay immutable semantic tables through buffered reads, reuse the disk projection's hot SQL statements and avoid identical graph-row rewrites; these optimizations preserve canonical bytes.

Unavailable optional grammars remain document/method outcomes under the existing native-context obligation, rather than duplicating it. A complete, currently validated native publication supersedes weaker-parser gaps for those captured inputs; producer assertions do not. Static syntax outcomes remain inspectable in either case.

Maven's existing passive online POM/JAR acquisition is retained and tested against exact external calls. Explicit offline selection remains offline. Unknown coordinates/signatures are never synthesized. Target lifecycles and generators still require isolated execution. Replace/extend this pack when stronger native bindings are available or a tested grammar/encoding is inadequate; preserve both evidence scopes and disagreements.

Continuation, 2026-11-04: scan now uses the replaceable `AnalysisWorkspace` port to spill completed neutral units, report populations, issue/gap sets and inherited gap lists before graph publication. Its filesystem adapter owns one append-only data file and a SQLite index, streams values and checks SHA-256 before reconstruction. Scratch bytes cannot select/load classes: reconstruction uses platform record/enum classes already encountered in this process. Sealed replay lists preserve canonical order, including Java UTF-16 ordering, remain valid through publication and fail after their owner closes. This is disposable scratch state, not durable semantic replay or native qualification. In-memory accumulation remains the compatibility implementation. Generic Java object deserialization and aggregate JSON buffering were rejected as unnecessary at this boundary.

JavaParser retains declaration skeletons for cross-file resolution and processes one full executable document body at a time. It preserves source ranges before detaching linked token streams; local, anonymous, lambda, record and Lombok identities remain source based. Declaration skeletons also drop lambda bodies in field/enum initializers; the full-body comparison covers this retention path. More parsing work trades for earlier body release. The regression compares neutral outputs against the full-body implementation. SDK verification streams bytes; non-class JAR resources are accounted for with a fixed buffer instead of retained as type input. Per-context neutral results, skeletons, source inputs and domain plans still require memory; oversized contexts can require a larger or partitioned worker. The installed 3.28.2 bytecode, upstream [facade source](https://github.com/javaparser/javaparser/blob/master/javaparser-symbol-solver-core/src/main/java/com/github/javaparser/symbolsolver/javaparsermodel/JavaParserFacade.java) and [API](https://javadoc.io/static/com.github.javaparser/javaparser-symbol-solver-core/3.28.2/com/github/javaparser/symbolsolver/javaparsermodel/JavaParserFacade.html) informed lifecycle inspection; focused controls own the implementation evidence.

Pinned framework-fragment semantics and declaration metadata no longer depend on an unrelated dependency's completion flag. Exact artifact tuples/hashes and local metadata/shape checks remain necessary; conflicting native aliases withhold the fragment. Overall classpath/registry gaps remain. An unresolved call attributed to an executable owner no longer invalidates the class’s constructor metadata; signature, annotation, generation and shape failures remain barriers. Observed source wiring triggers Spring plan/truth evaluation even when scan membership is open. The repository denominator is retained once; each automatic Spring slice inherits global plus its own analysis gaps, avoiding multiplication by unrelated modules. This does not invent bootstrap, registration order, profiles, parent containers or runtime closure.

Captured native observations are joined to their authenticated census and projected into symbol references and import/type/heritage/call/state/annotation bindings. `polyglot.asserted.*` retains producer assertions; `polyglot.native.*` requires validated-observation publication trust. Target sets and uncertainty evidence remain. These are compile-time bindings with `runtimeObserved=false`, not observed dynamic dispatch. Missing optional symbol/caller metadata produces typed projection gaps without discarding observations. Syntax edges confer no callee authority. Native execution still requires an available registered executor/context; passive fallback does not impersonate one.
