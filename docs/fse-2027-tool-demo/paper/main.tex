\begin{abstract}
Modern Java and polyglot enterprise repositories rely heavily on build plugins, conditional dependency injection (DI), and cross-service protocols, posing two coupled challenges for software evolution tools: executing untrusted target builds on an analysis host compromises security, while single-configuration or static-only approximations flatten conditional Spring bean truth and overlook test-suite overfitting in automated refactoring. We present \textbf{Evo Workbench}, an online, host-safe architecture intelligence and verified evolution platform. Evo runs passively (\texttt{--build=off} / \texttt{EVO\_ONLINE\_MODE=true}) to recover canonical Software Knowledge Graphs (SKGs), models conditional Spring bean truth (\texttt{MUST}/\texttt{MAY}/\texttt{NEVER}/\texttt{UNKNOWN}) with content-addressed SHA-256 replay, exposes \textbf{23} read-only tools and \textbf{7} resources over Streamable HTTP MCP (\texttt{2025-11-25}) with strict origin enforcement and secret redaction, and certifies candidate patches across a pinned multi-JDK (\texttt{8}/\texttt{11}/\texttt{17}/\texttt{21}) sandbox using \textbf{22} deterministic AST/OpenRewrite recipes and 3-layer verification.
\end{abstract}

\section{Introduction and Motivation}
Architecture recovery, comprehension, and automated refactoring tools often assume unrestricted host execution—invoking Maven or Gradle build plugins directly on developer workstations, flattening conditional Spring configurations into a single active world, or accepting plausible patches that pass tests via hollow method stubs~\cite{swerefactor2026}. Conversely, pure static tools that discard provenance or conflate derived flows with direct syntactic facts sacrifice auditability.

\textbf{Evo Workbench} resolves this tension for practitioners and AI coding agents through a turnkey online web workbench (\texttt{evo-workbench-online:latest}, \texttt{backend/target/evo-workbench.jar}) built around deterministic canonical snapshots, explicit uncertainty reporting, and networkless container isolation.

\section{Architecture and Safety Invariants}
Evo enforces a unidirectional pipeline: \textit{acquisition $\rightarrow$ build model $\rightarrow$ semantic frontend $\rightarrow$ Spring enrichment $\rightarrow$ canonical graph $\rightarrow$ query/metrics/policy $\rightarrow$ presentation}. Six non-negotiable invariants govern all workbench surfaces:
\begin{enumerate}
  \item \textbf{Execution Safety (\texttt{I1}):} Untrusted target builds never run on the host; online acquisition runs passively (\texttt{--build=off}) and repair execution runs strictly inside networkless read-only containers (\texttt{--network=none --read-only --cap-drop=ALL}).
  \item \textbf{Deterministic SHA-256 Replay (\texttt{I2}):} Identical inputs yield bit-identical canonical JSON digests across cold and warm incremental runs.
  \item \textbf{Closed Reporting Denominator (\texttt{I3}):} Unresolved, partial, timed-out, or missing-dependency outcomes emit typed \texttt{CapabilityGapRecord} entries; coverage and confidence are reported separately from architecture health scores.
  \item \textbf{Trust Tiers and AI Quarantine (\texttt{I4}):} Compiler/bytecode, source syntax, declarative config, derived DFD exports, and advisory LLM outputs remain strictly separated (\texttt{canonicalLeakage = 0}).
  \item \textbf{Zero Benchmark Overfitting (\texttt{I5}):} Production code contains zero benchmark-specific identifiers or corpus shortcuts.
  \item \textbf{Comprehensive Coverage (\texttt{I6}):} Generated sources and stubs are accounted for without silent truncation.
\end{enumerate}

\section{Multi-JDK Isolated Repair and Certification}
Inside the \textbf{SKG-RTS Repair Studio}, Evo prioritizes \textbf{22} deterministic AST/OpenRewrite~\texttt{8.87.7} recipes—covering both DI cleanups and compound object-oriented refactorings (such as \texttt{EXTRACT\_AND\_MOVE\_METHOD} and \texttt{BREAK\_PACKAGE\_SCC\_CYCLE}~\cite{swerefactor2026})—before free-form LLM proposals. Candidates pass through dual-slicing causal context~\cite{causalrepair2026}, QMOOD Understandability non-regression guards~\cite{refagent2026}, and two-tier isolated verification:
\begin{itemize}
  \item \textbf{Tier-1 Fast Loop:} Hardened networkless container (\texttt{JDK 8/11/17/21} auto-detected passively from \texttt{pom.xml}/\texttt{build.gradle}), read-only \texttt{.m2} bind mount, \texttt{SKG-RTS} affected-test filtering, and XXE-hardened JaCoCo coverage parsing (\texttt{UNKNOWN\_UNTESTED} when \texttt{0\%} covered).
  \item \textbf{Tier-2 Certification:} Hypervisor-level 3-layer certification requiring \textit{Compile\&Test + Coverage} $\land$ \textit{AST Refactoring Purity} $\land$ \textit{Negative Control} (confirming the baseline finding persists on control mutation and resolves on the candidate).
\end{itemize}
