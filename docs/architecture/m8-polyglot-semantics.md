## Census and promotion rules

Each census row identifies a document, A01–A12 category and obligation key in one exact context. Every emitted row must reference the exact corresponding obligation identity. Unknown keys, foreign contexts, contradictory status/target shape, absent expected rows or missing document/category populations cannot silently close coverage. A01/A11/A12 cannot be disposed as NOT_APPLICABLE.

Two separately registered predicates are required for completion: `polyglot.census:m8.4-v1` with `INDEPENDENT_CENSUS`, `DOCUMENT_MEMBERSHIP`, `CATEGORY_CLOSURE`; and `polyglot.observations:m8.4-v1` with `CALLER_TARGET_ORIGIN`, `SOURCE_COORDINATES`, `APPLICABILITY_VALIDATED`. Both use the existing opaque `EvidenceVerifier.VerifiedClaim` capability, the same exact request/input/toolset/policy and the canonical proof payload binding all three tables. Target JSON, a hash, an exit code or a producer trust label cannot construct that capability.

Revoked proof, unavailable source bytes, changed live policy, pending categories or unresolved/unsupported/error/candidate/ambiguous/partial/conditional outcomes prevent completion. Partial/conditional/ambiguous rows require explicit uncertainty; one candidate is never promoted solely because it is the only one. Category/occurrence accounting is separate from correctness and pack qualification. The authored Ed25519 test authority checks this protocol only and stays in test sources. No production validator method is registered by this change.
