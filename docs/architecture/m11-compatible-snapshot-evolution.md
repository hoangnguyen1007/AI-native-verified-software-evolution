# M11 — Compatible snapshot evolution contract

**PROVISIONAL — implementation design from M11.1, 2026-11-14.** [ADR-010](../decisions/ADR-010-compatible-snapshot-evolution.md) records the alternatives. The public shapes below are proposals for M11.5. [M10](../tasks/m10/01-release-sign-off.md) authorizes M11; existing M1–M8 wire formats, score formulas, trust labels and release reservations remain authoritative. See [protocol and cases](../tasks/m11/PROTOCOL.md) for the verification denominator.

## 1. Ownership and inputs

`analyzer` owns compatibility, correspondence, proofs, deltas and the query port. `analyzer-filesystem` verifies immutable graph/evidence pages and maintains disposable sort indexes and durable content roots. Backend supplies authenticated report/receipt readers and job/HTTP adapters; CLI and Workbench consume the same domain queries. SQL and transport never define a match, absence or lifecycle outcome. An input is an explicitly pinned artifact revision, not a mutable branch, live path, cached result or UI filter. A stored-graph read never executes target code; any new target capture follows [M8.4](m8-repository-readiness.md).

| Input/field | Real producer and availability | Guard |
|---|---|---|
| Repository/snapshot identity, inventory, revision provenance | `RepositorySnapshot` / `repository.snapshot`; streaming ingestion inventory and acquisition roots when published | Validate reference closure and source inventory; revision and dirty flags are provenance, not semantic keys. A caller-supplied repository string alone cannot establish lineage. |
| Graph and materialized context IDs, context evidence, nodes and edges | `KnowledgeGraph` / `GraphSnapshotCodec`; authenticated partition archive. `PartitionedGraphReader` supplies partitions, nodes and adjacency; `PartitionedGraphStore` has exact evidence lookup | Existing port lacks paged context descriptors, global edge/evidence scans and general report joins. Use outgoing adjacency once per node and verify against the exact partition edge census, or add a neutral ordered edge scan. Do not use the lightweight `GraphManifest` shortcut as a full archive integrity check or its saturated `int` counts as exact totals. |
| Expected root/module/source set/variant/language census | `build.model`, `build.module`, source ownership/requests and optional readiness/polyglot census from acquisition | Materialized partitions do not prove expected context closure. Keep missing obligations, inactive/not selected contexts and unknown variants, including contexts with no graph rows. |
| Java analysis/profile and logical entity keys | `analysis.manifest` (`AnalysisManifest`, ordered `ClasspathEntry` list), Java context/source-plan evidence, `EntityIdentity` (origin, `EntityScope`, kind, canonical `java:v1` symbol); `ModuleIdentity` binds repository + relative path | The manifest embeds a compact snapshot reference; artifact digest/version do not guarantee binary bytes are retained. Bind platform/tool/provider digests where supplied. Treat missing proof as unknown, including effective Maven/Gradle choices. |
| Spring definitions, configuration space, registration, truth/witness evidence | `spring.context`, plan, explicit worlds and symbolic DAG from `CanonicalGraphBuilder`; `ConfigurationSpaceIdentity`, `TruthRegionEvaluation` and `SymbolicTruthRegions` | A plan-only graph, opaque registration order or unknown external environment is not a closed world. Derive proof with M4/M5 reasoners; do not trust same region hash across captures. |

Raw graph may retain syntax only or an explicit bridge projection | Use producer-qualified logical symbol where exposed; `SemanticCorrespondence` currently governs same-snapshot question carryover, not cross-snapshot identity. Source bodies and binaries need not be present; evidence tier is optional receipt metadata. A manifest-only graph or missing receipt cannot fill the gap or promote trust. |

`comparisonPreparation` is an M5 diagnostic using manifest/Spring policy descriptors. M11 consumes original authenticated operands, not its Boolean. Partition counts, bounded pages and passive `950‰` completion describe their own denominators only.

## 2. Canonical identities and completion

Define `H(tag, fields) = SHA-256(UTF-8(CanonicalJson([tag, fields])))` with lowercase `sha256:` digest strings. Canonical records have sorted fields, explicit null for absent optionals, exact integer/decimal values, and no floats; unordered rows sort by canonical key and duplicate keys are rejected. Preserve order for left/right, ordered classpath, directed routes, world order and declared history. A neutral `ArtifactRef` carries `schema`, `digest`, and expected context/owner where relevant; status distinguishes `AVAILABLE`, `NOT_REQUESTED`, `MISSING`, `CORRUPT`, `UNSUPPORTED`, `PENDING`. An unknown size/count is null with an explicit completeness status.

| Identity / tag | Fields in preimage |
|---|---|
| `architecture.evolution.request:v1` | `left`, `right` immutable side descriptors (repository, snapshot, graph, expected referenced roots for census/evidence/reports), `mode`, normalized `selection`, `history` or null, `correspondencePolicy`, `versions`, `workPolicy`. Exact graph/evidence roots bind their bytes, including embedded provenance. |
| `architecture.evolution.context-key:v1` | Repository lineage, context family, typed logical root/module/source-set/variant/language/dialect or applicability sentinel, plus context role and authoritative parent match when applicable. No provider execution ID or source digest as a logical field; compare those as inputs. |
| `architecture.evolution.subject:v1` | Subject family and match operands below under authenticated scope. An exact match uses equal canonical subject data; producer correspondence carries the ordered mapping and proof references. Unmatched subjects use side-qualified references and cannot acquire continuity via their local key. |
| `architecture.evolution.finding-key:v1` | Rule semantic key (stable policy namespace and rule ID, predicate version/kind, scope, normalized selectors, relationship kinds, parameter operands), mapped context, predicate subject and route shape with mapped directed semantic relationship discriminators. Severity is an independent axis; an unproved rule version transition is drift. Region, evidence, spans and snapshot keys are excluded from logical matching. |
| `architecture.evolution.event:v1` | Request key, family, subject, event kind, canonical scoped region or null, before/after authenticated references, support/qualification and typed-gap references. |
| `architecture.evolution.result:v1` | Request key, realized input dispositions, authenticated census and correspondence roots, ordered event root, compatibility/proof/coverage/gap roots, deterministic residual work and domain outcome. Use row-stream or paged content roots with a canonical logical row preimage independent of transport page size. |

`versions` binds algorithm/schema/matching policy and all result-affecting provider, rule, projection, metric/score and reasoner semantic identifiers/digests not already bound in the roots. `workPolicy` binds deterministic matching, solver and traversal limits; scheduling, retry timings, memory allocations that only pause processing, job IDs, cursors, absolute host paths and observation timestamps outside immutable inputs live in receipts. Exact artifact identity can change when embedded telemetry changes; semantic events must stay empty for telemetry-only edits. No comparison key is a proof of semantic equivalence.

A canonical result is `COMPLETE` when all requested work is discharged under the declared mode, `PARTIAL` when some requested work remains as a deterministic, typed residual, and `WITHHELD` when no requested inference is allowed and there is no useful qualified comparison in that mode. A fully accounted but intrinsically opaque fact can still have `UNKNOWN` truth; a missing operand or unfinished proof leaves a residual for the dependent operation. `QUEUED`, `RUNNING`, `WAITING_FOR_RESOURCE`, `CANCELLED`, `FAILED` and `SUCCEEDED` are operational states. Cancelled/interrupted attempts may retain verified checkpoints, never publish an interrupted prefix as final. Request-key reuse must revalidate pinned roots, availability dispositions and result bytes. Missing data restored is a different realized input and must be reconsidered. Conflicting results for the same request **and realized inputs** disable reuse for that tuple and retain both artifacts.

## 3. Compatibility, census and correspondence

`STRICT` returns semantic deltas only where the requested capability has proved compatibility and the event has sufficient evidence. `OBSERVATION` can additionally show before/after observations and drift, including for a capability where the semantic delta is withheld. Neither mode bypasses integrity, dependency closure or trust. Assess each capability (`STRUCTURE`, `SEMANTIC_RELATION`, `REGION`, `BINDING`, `EVIDENCE`, `FINDING`, `HISTORY`, `METRIC`, `SCORE`) for each selected scope. Record per-dimension reasons, operand references, and allowed/withheld operations; do not collapse to a Boolean.

| Verdict | Meaning |
|---|---|
| `COMPARABLE` | Authenticated, compatible operands for that scope/capability. A specific event still needs proof. |
| `QUALIFIED` | Both observations readable; known drift or a restricted scope permits only separately identified claims. A proved sub-scope gets its own row. |
| `INCOMPATIBLE` | Known disjoint or incompatible semantics with no accepted mapping/adapter, e.g. different repository lineage for lifecycle. |
| `UNKNOWN` | Missing or unproved compatibility operand, scope closure or continuity. |

Validate graph schema, repository/lineage, context and identity schema first. Then compare only the dimensions that capability needs: producer/tool bytes and configuration; root/module/source set/variant, platform and **ordered** classpath; typed configuration and registration semantics; rules, metric definitions and score model; result-affecting limits; evidence tier and closure. Keep digest differences for source-bound input separate from policy drift (derive by typed field, never blanket-drop values). For example, changed snapshot or reactor source content can be normal, while changed dependency bytes/order or framework policy qualifies dependent facts. Unsupported schema or corrupt graph/sidecar cannot support claims in any dependent scope; an unrelated independently verified scope can remain comparable. Report attribution dimensions separately; simultaneous changes are mixed/unattributed unless a separate controlled replay isolates a cause.

Enumerate both expected and realized context populations. Each side has exactly one disposition per row: `MATCHED`, `LEFT_ONLY`, `RIGHT_ONLY`, `AMBIGUOUS`, `UNAVAILABLE`, `NOT_SELECTED`. Count a matched pair once on each side, list candidate links separately, and keep unknown expected census as unknown rather than zero. `LEFT_ONLY/RIGHT_ONLY` mean authenticated one-sided observations; calling a context removed/added needs closed opposite descriptor/ownership census. `NOT_SELECTED` is never absent. Selection is explicit and normalized; history intervals and unavailable parents stay visible. Aggregate compatibility cannot outrun transitive input closure of the selected proof.

Use authenticated repository lineage and stable scoped keys first, then unique canonical language symbols under a proved context/module mapping, then independently verified producer correspondence. Reject incompatible origins, conflicting candidate sets and non-bijective matches; a more specific heuristic cannot override a conflict. Keep ambiguity and split/merge observations, never choose a rename by score, location or FQN. For v1, exact repository/root/module path/typed dimensions are the default; operator assertions and unproved relocations have no canonical matching authority. Java overload, local/nested identity and generated lineage remain intact. Record an origin change as a separate observation unless independent evidence establishes continuity. For polyglot facts without a verified language logical key, restrict comparison to their declared observation family and tier.

Relationships use mapped directed endpoints, kind and a producer-defined discriminator; do not align an unresolved target to a resolved one by spelling. Compare semantic payload, occurrence multiplicity, spans/locations and support independently. A source file move with unchanged symbol/scope can affect location alone. A directed cycle key uses the lexicographically least rotation of the ordered typed vertex/edge sequence; never reverse it. Preserve both M6 finding references and both source/evidence paths, even when their logical key aligns. Report- or rule-level truth does not prove that a particular route is absent without corresponding route/selector coverage. Witness path changes alone do not change rule predicate identity; independent logical routes remain separate findings.

Compatibility rows carry `scope`, `capability`, `verdict`, `reasons`, `allowedOperations` and `withheldOperations`. Each reason carries a dimension and typed code, side(s), and authenticated operand references or the expected artifact/disposition. Keep `INPUT_CORRUPT`, `INPUT_UNAVAILABLE`, `SCHEMA_UNSUPPORTED`, `LINEAGE_UNPROVED`, `CONTEXT_AMBIGUOUS`, `TOOL_DRIFT`, `CLASSPATH_DRIFT`, `RULE_DRIFT`, `DOMAIN_CORRESPONDENCE_UNPROVED` and `COVERAGE_UNPROVED` distinct. These are comparison diagnostics; link original typed gap records where applicable instead of replacing them with display messages. A canonical decision never relies on an error string, HTTP code or UI color.

## 4. Proofs, lifecycle and numeric comparison

An absence proof names side, subject or query predicate, context, projection, rule (if applicable), region, exact census/coverage operands, and verifier/version. It requires authenticated inputs, applicable rule or fact predicate, complete coverage for the relevant positive and negative population, no relevant blocked frontier, and a definite negative in that scope. A scoped source census can prove a declaration is missing from that census; it cannot prove no dynamic or generated declaration exists without the matching obligation. Missing/corrupt evidence, incomplete coverage, disabled policy, solver exhaustion and an empty result page provide no negative proof. Use typed `CapabilityGapRecord` with original provenance where a real snapshot/context exists; for missing input before a valid context exists, retain typed input failure without fabricating an identity.

Align typed variables, values (including `MISSING` and `OTHER`), defaults/precedence envelopes, constraints, feasible worlds and material registration order through a proved injective mapping on each side of `Kc`. First support exact typed domain/semantics; M11.3 may prove common subsets with changed domain values or constraints. The same key name or world ID is insufficient. Distinguish proved feasible side-only worlds from `UNMAPPED`/`UNKNOWN_FEASIBILITY`; only proved side-only worlds support `DOMAIN_ADDED/REMOVED`. Side-only and unknown worlds cannot produce fixes. Preserve original and common-domain quantifiers separately. On nonempty fully covered Kc with U empty: all T → MUST, all F → NEVER, both → MAY; otherwise UNKNOWN. Empty Kc is explicitly empty, with no vacuous MUST/NEVER.

On Kc, derive `introduced = F_left ∩ T_right`, `resolved = T_left ∩ F_right`, `persisted = T_left ∩ T_right`, `clean = F_left ∩ F_right`, and `uncertain = Kc \ (introduced ∪ resolved ∪ persisted ∪ clean)`. Only certified T/F intersections establish events. Unknown remainder cannot be assigned by subtracting T sets. Expansion/shrink/equivalence require proofs of inclusion or equality of true membership on Kc, or emit proved gain/loss subregions with unknown total shape. Reshaped needs both gains and losses; an unfinished proof reports that limit. Use existing symbolic reasoner or finite-world oracle; preserve DAG references and proven regions when a budget stops reasoning. Distinguish candidate, activation, registration, selected binding and runtime evidence. Each witness/counter-witness binds side, context, region, semantics and replay type. A changed representative is an evidence delta; formula replay is not runtime replay.

| Before → after, per comparable region | Result |
|---|---|
| `ABSENT → PRESENT`, `PRESENT → PRESENT`, `PRESENT → ABSENT` | `INTRODUCED`, `PERSISTED`, `RESOLVED` respectively, with corresponding positive/negative proof. |
| `UNKNOWN → PRESENT`, `PRESENT → UNKNOWN` | Newly observed or evidence lost/uncertain; never introduce or resolve solely from missing knowledge. |
| `ABSENT → ABSENT` | Proven clean on that region only. |
| Remaining transitions involving `UNKNOWN` | Preserve the knowledge transition and typed reason; no definitive lifecycle label. |

History is ordered side descriptors plus authenticated parent edges or an explicit sequence declaring each interval and its proof. Timestamps do not supply adjacency. Compare interval continuity for the same logical rule, subject and regional operands; validate correspondence composition without assuming transitivity. `REINTRODUCED` needs `PRESENT → proved ABSENT → PRESENT` in a continuous declared scope, with no unknown interval between those witnesses. Incomplete paths or unselected merge parents cannot justify global continuity. `earliestObserved` is bounded to the declared lineage/interval. A pair can contain distinct introduced/resolved/persisted subregions for one finding.

Metric/score output carries original values, exact operands, units, rounding, definition/model/parameters, projection, denominator and applicability. Emit `after - before` only on compatible definitions and adequately reconciled population. Legitimate population growth can be compared with an explicit denominator change; filtering, model drift or unknown counts qualify/withhold a delta. Relative percent is null at a zero baseline. Carry M6 calibration, contribution and evidence qualifiers. Evidence loss cannot be presented as a health improvement, even if two original published values exist. Gap changes follow obligation/context/root cause and ledger resolutions; omission does not prove a gap resolved. Keep operational, semantic, evidence and health axes separate.

## 5. Persistence and consumer proposal

Use verified immutable event/census/proof roots and a single atomic terminal reference after referential and content checks. Retain job progress, checkpoint high-water key and the exact pinned inputs; use ordered sort/merge on paged readers and disk indexes to bound resident memory. If the worker cannot admit a row/page, wait/resume or report typed residuals. There is no total-repository ceiling. Resume only under the same input and work-policy identity. Validate concurrent publication; equivalent results are idempotent, conflicting results stay separate and visible. Avoid a hidden full-graph fallback on a cold read.

| Proposed local HTTP `/api/v1/evolution` route | CLI equivalent / meaning |
|---|---|
| `POST /jobs` | `evo evolution compare --request FILE` submits a strict versioned request referring to registered immutable inputs; no host paths/commands in the HTTP body. |
| `GET /jobs/{job}`, `POST /jobs/{job}/cancel` | Status/progress/cancel by job receipt; terminal view links to verified result or typed stop. |
| `GET /results/{result}`, `POST /results/{result}/query` | `evo evolution inspect RESULT` reads summary or typed paged compatibility, census, events, regions, bindings, lifecycle, history, metrics, score and side evidence. |
| `GET /results/{result}/export` | `evo evolution export RESULT` streams canonical JSON through the same selection and redaction rules; full export respects response bounds via authenticated chunks/continuation, with an explicitly identified authorized local export for larger artifacts. |

Reuse existing loopback/origin, strict JSON and [M7 HTTP](m7-query-http-api.md)/[M8 job](m8-analysis-jobs.md) conventions. Success is versioned `data` with canonical digest, including known domain PARTIAL/WITHHELD; submission 202, idempotent retry 200, malformed operands/foreign cursor 400, missing publication 404, conflicting idempotency key 409, oversized response 422, busy/unavailable 503. Integrity errors fail closed with a sanitized typed reason. Bind cursor to result, operation, filter, side, stable ordering, page size/schema and last key. `exactTotal` is null when unknown; a lower bound and partial outcome may coexist. CLI exits 0 for complete, 3 for partial/withheld with a valid result, 1 for operational/I/O failures, 2 for invalid input and 130 for canonical cancellation per M7 conventions. No separate arithmetic in UI/export. Side evidence is immutable and redacted using existing allowlists; public hashes must be for the actual redacted payload and distinct from internal artifact identities when bytes differ. The Workbench displays direction, scope, provenance, unknown regions and degraded states and guards against stale responses.

The [compact examples](../tasks/m11/cases.json) are logical payload fragments and independent expected outputs, not produced data. A positive pair matches scoped Java `p.A`/`p.B`, proves no baseline `A→B` in the closed structural population and emits `RELATION_ADDED`. A degraded pair preserves the same previous observation but cannot read the target's support for that relation: `PRESENT → UNKNOWN`, `PARTIAL`, typed gap, no `RELATION_REMOVED` or `RESOLVED`. An empty event page is not evidence of no change.

## 6. Implemented M11.2 boundary

`SnapshotComparison` is the internal service and `FileSnapshotComparison` is its paged, external-memory adapter. Their output sections expose exact row counts and canonical row-stream digests. These sections are internal and are not the proposed wire contract in §5. The adapter opens immutable graph IDs, verifies graph roots and reads their canonical context/node/edge/evidence pages. An optional report reference is authenticated against exact graph/context membership through `PublishedReports.verifyEvolutionReport`; it contributes an input disposition, not a finding or coverage assertion. The disk sort/index is request-private and the session owns its lifetime. It has no public endpoint or durable resume after process failure yet.

Definite structural deltas are scoped to supported Java declarations and selected Java relationship kinds, including `graph.depends-on`. A negative proof uses the exact captured source-plan document census, frontend result membership, processed source outcomes and applicable category coverage. The implementation validates raw relationship identities and type-owner projection before using edge evidence. Inconsistent same-source output, unresolved/candidate targets, declaration gaps and an unsupported provider cannot support removal. Evidence and span changes remain distinct from semantic payload and multiplicity. Legacy publications with placeholder analyzer/rule digests stay qualified or unknown; no binary identity is fabricated for them.

The census retains materialized partitions, source sets derived from available build modules and independently reported missing or unselected inputs. Known build component and polyglot dimensions, producer trust, and graph gap records remain inspectable; a repository-wide expected census is unavailable unless supported by recorded producer inputs. Exact Java scope, source-set name and available root/variant dimensions are used; no inferred rename, generated declaration continuity or cross-provider symbol promotion is performed. Conditional regions, bridge/binding proofs, finding lifecycle and assessment deltas have their own later tasks. See [M11.2 execution and limits](../tasks/m11/02-execution.md).
