# M8.3 — Structure, configuration and evidence workbench

**CONFIRMED human request:** finish M8.3 with working, understandable English interactions, truthful repository data and verified UX. The later comprehensive-coverage mandate is binding: presentation limits must never silently become analysis exclusions or evidence of absence. Acquisition/generated-code/readiness work remains governed by the original safety and provider contracts.

## Boundaries and versions

The browser consumes canonical queries and published reports. It performs layout, navigation and a labeled comparison of two loaded result sets; it does not solve conditions, calculate metrics or scores, execute target code, or compare repository history. Query/cursor identities advance to `architecture.query:m8.3-v1` because source-root/candidate descriptions and new operations affect returned canonical values. Visual projections advance to `graph.projection:m8.3-v1` for actual focus-depth bounds, retained evidence/status and request-bound identity. M1 identities, graph snapshot schema, source/Spring facts, policy/metric/score formulas and symbolic choice preimages are unchanged. HTTP paths remain additive v1; OpenAPI advertises M8.3.

The simple baseline of scanning every relationship page in the browser was rejected: it mixes ownership with dependencies, repeatedly downloads unrelated relationships and makes continuation/error handling difficult. Direct `children` queries retain ownership in the domain service. A client-side condition evaluator was rejected because it would duplicate the solver, bypass provenance and risk false certainty. Replay stays behind the canonical query service. These are reversible implementation choices within the requested slice, not a new semantic/scoring model.

## Canonical operations

- `queries/children`: `{identity}` plus a page. Returns direct `graph.contains`, `graph.declares` and `graph.owns-source` targets in one exact context, deduplicated and identity-sorted. Parent context, population, scope, budgets and cursor binding are enforced. Dependencies are never treated as children. Java and acquisition contexts remain separate; the explorer does not invent a cross-context hierarchy.
- `queries/realizations`: paginated recorded explicit worlds and deterministic solver-proved symbolic examples. Examples do not enumerate the full configuration space. Incomplete assignments are qualified and never offered as a full realization. Requests retain the upstream exact world or Boolean assignment. Optional `profiles` describes **baseline** profile Booleans only. Explicit record/map encodings are handled; symbolic choices use the compiler-owned baseline-choice key. Property names/values and source choices remain redacted; profile precedence/includes/groups must not be inferred from baseline labels.
- `queries/metric-definition`: `{metric}` retrieves the canonical catalog definition, meaningful scopes, formula, unit, population and limitations. Unknown IDs are rejected; absent providers retain a typed gap. The original metric catalog and value routes remain available.
- `reports/{report}/replay`: `{identity: findingIdentity, counterWitness: boolean}` selects only a published finding and its captured witness/counterexample. The domain service rebuilds the original rule predicate/region, checks the region identity and evaluates that exact world/assignment. Foreign/missing findings/witnesses, wrong types, stale regions, resource exhaustion and missing evidence stay explicit. A structural constant can have an empty assignment; an incomplete symbolic assignment cannot become a successful replay. `formulaReplayed` and `semanticReplayed` stay distinct; this operation never starts Spring or reruns semantic extraction.

## Usable inspections

Structure offers module/package/class/member/source-file/source-root entry points, recorded containment, breadcrumbs, Back, search, origin/source-set filters, direct details, incoming/outgoing dependencies, impact, focused graph and metric drill-down. Empty/default package names have a readable label. Source roots are labeled only by matching the builder's recorded root identity to the build descriptor; owned documents expose validated relative paths/hashes, never source bytes or host paths. Candidate names come only from exact declared-name evidence.

Configurations compares two selected projections or realizations within one context. Spring scope uses `spring.selected-binding`; Java structural scopes use `graph.depends-on`. Loaded dependency identities are resolved to canonical entity names in bounded batches. A missing row is labeled absent only when that side is complete, untruncated and fully paged. Otherwise it is **Not established**. Each side retains its request, status, bounds, gaps and continuation, with details, further pages, graph navigation and JSON export.

The graph supports bounded scopes/projections, real one/two/three dependency-step focus, node details/expansion, shortest jointly feasible paths, source evidence, zoom/fit and JSON/PNG export. The traversal service counts vertices; focus translates dependency steps to that existing bound, including the CLI consumer. HTTP focused depth must be an exact integer 1–19 with a seed; fractional/overflow/string or ignored depth-only arguments are rejected. Parent compounds close irrespective of ordering. Spring realized/MUST/MAY nodes use canonical selected definitions, rather than every captured candidate; unknown alternatives remain explicit in union/uncertainty views. Projections retain query and cycle statuses/bounds/gaps, edge supports/regions/evidence, and request/result identity. Keyboard node/path controls and line-style/text legends complement the canvas. PNG uses the [Cytoscape nonblocking Blob export](https://js.cytoscape.org/#cy.png), with the same object-URL download path as JSON.

Metrics defaults to captured inventory in Java contexts and Spring inventory in Spring contexts. Definitions determine applicable scopes; incompatible scope changes return to the explicit context subject. Counts/ratios/units/rankings/statuses remain backend values. Missing policy has a direct Configure rules & scoring action and a reviewed cycle-check example; it never creates a default healthy score. Score dimensions, withheld reasons, policy metrics, findings, source spans, model replay and JSON remain reachable. The example is an editable policy, not a claim of complete architectural coverage.

## UX and acceptance boundary

Native controls/dialogs and the existing local Cytoscape renderer are retained; no framework migration or runtime CDN is needed. Detail disclosure limits main-view density. Async views use abort/generation checks, busy/status announcements and explicit retry/empty/partial states. Horizontal tab arrows/Home/End move focus; Enter/Space activates an API-loaded tab. Focus margins, wrapping controls, responsive cards and bounded table scrolling protect narrow viewports. Primary actions stay at least 44 CSS pixels high.

Applied primary guidance: [W3C tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) recommends manual activation when loading adds noticeable latency; [WCAG reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) distinguishes ordinary content from tables/diagrams needing two-dimensional layout; [Carbon data tables](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines) guides headings, toolbars and expandable detail. These choices are not a blanket WCAG certification.

Acceptance uses a captured external MiniChatServer commit plus source-generated Framework 6.2.0/Boot 3.4.0 conditional fixtures and negative controls. Register and report actual environment, view sizes, timings and outcomes in the task record. Approved traversal bounds remain 20 vertices of path depth, 100,000 steps and 50 cycle witnesses. Local measurements do not establish a global latency SLA. Mandatory M8.4 comprehensive readiness work precedes M9 scale/accessibility/usability review and M10 human Track A acceptance; Track B stays gated.
