## Encoding and common types

Reuse Step-3 [wire rules](m8-isolated-execution-schemas.md#common-wire-rules) and existing `CanonicalJson`: UTF-8, sorted UTF-16 object keys, exact scalar strings, no implicit Unicode normalization, duplicate keys/unknown fields/invalid surrogates rejected. `Digest` is `sha256:` + 64 lowercase hex. `Handle` has digest and nonnegative signed-long size. M1 snapshot/module IDs keep their `snapshot:sha256:` / `module:sha256:` prefixes. No identity field is hashed recursively into itself: a top-level record's ID is the external SHA-256 of its complete canonical record bytes.

`Table` is `{schema,content:{digest,size},rows}`; canonical NDJSON, one canonical row plus LF, no BOM/header. Row schema and sort key are fixed below. An empty table has zero rows and the real SHA-256/size of zero bytes. Do not use a placeholder digest. U64 here means 0..9223372036854775807; JS must parse/project losslessly. Byte offsets/counts use checked arithmetic. Tables are streamed/external-sortable; no global maxItems defines repository admissibility.

The implemented table scanner additionally returns an opaque per-table cursor with checked 64-bit row/byte positions. MORE and CANCELLED retain an open frontier; END requires exact declared rows and EOF. Checkpoints use the internal `java-evidence-table-cursor:m8.4-v1` payload (`table`, `rows`, `offset`, `previous` row digest). Restoring untrusted checkpoint JSON replays its exact sorted prefix under a worker replay budget; a content hash alone cannot authorize skipping rows. A malformed tail or consumer rejection retains the last validated cursor. Unknown record kinds are rejected even for an empty table. This operational checkpoint is separate from the 17-record semantic wire union and does not certify generation or semantic completeness. The legacy full-table reader remains available; closure requirement loading uses bounded scan batches.

Structural examples can use synthetic non-resolving handles; they must never enter a real evidence store as verified records. Shape acceptance does not establish table content integrity.

`Scope` binds inventory, optional compatible base snapshot, readiness, selection, context, stable logical-scope digest, module ID, named source set and variant. `context` is the exact `ReadinessPlan.Context.identity()`, not `Context.id()` or the module ID. Logical-scope preimage is `CanonicalJson({schema:"java-logical-scope:m8.4-v1",repository,root,moduleKey,sourceSet,variant})`, where repository is the existing repository identity and root/moduleKey are the exact logical keys in the referenced plan, not absolute host paths. Validate every redundant field against the referenced plan/context.

`Locator` binds original container handle, ordered archive member steps `{path,ordinal,content}`, and final raw `LogicalPath`. A plain exported file has no archive steps. Directories use their entry-table handle as container; each member step's content is verified against its parent. For an absent expected output, container is the verified expectation/census artifact defining the location, not invented file bytes; content stays null. A diagnostic display path is never a locator. `Ref` references a content-addressed typed record; the schema uses Digest at these sites, and the validator enforces expected target type. `gaps` and `gapRefs` instead preserve existing `gap:sha256:<64 lowercase hex>` identities; they are not plain digests.

Collections are ordered sequences unless declared sets below. Sets sort by the cited row key or canonical JSON encoding; reject duplicates instead of silently dropping them. Null is only permitted where declared, and means unknown/not yet available or inapplicable under the contract, never known empty. Every unknown required semantic input must have an explicit frontier/gap record.

## Table schema names and sort keys

The `table.schema` value is `<row-schema-prefix>-table:m8.4-v1`; rows themselves include their normal record schema. For input tables sort `(role, canonical locator, content.digest)`; lineage/proof/decision/binding tables sort external record digest; output rows sort `key`; resolution slots sort `(space,ordinal)` using enum-name lexicographic order between spaces, never between ordinals; requirements sort requirement key; current rows sort requirement; source-map rows sort projected path. Preserve distinct duplicate-content slots. Duplicate logical keys with different rows are a validation error/conflict.

Source membership and correspondence tables reuse `java-evidence-input` rows, with roles `SOURCE_MEMBERSHIP` and `CORRESPONDENCE` and content pointing to independently typed verified evidence. The **payload contracts** are:

- SOURCE_MEMBERSHIP payload: exact scope, source document or generated locator, content hash, source-root proof, named source set/role and INCLUDED/EXCLUDED/UNKNOWN disposition with reason. Every candidate document has one disposition; UNKNOWN prevents exact source closure.
- CORRESPONDENCE payload: exact scope, original source/document/member identity when present, generated locator or binary class/member descriptor, source/binary input hashes, SAME_DECLARATION/AUGMENTS/CONFLICT/UNKNOWN outcome, predicate/proof and supporting spans. Bytecode-only source location is null. Each declared mapping must be independently checkable; absence of a map never means equivalence.

These two payloads are defined structurally as `java-source-membership` and `java-correspondence` in the same JSON Schema. They are not arbitrary free-form JSON. Legacy source span and entity identity values are referenced by immutable evidence handle rather than copied into an incompatible second M1 schema. Resolve and validate them with existing M1 codecs.

The source/native adapter uses the existing M1 `Entity` as `sourceEvidence`: SAME_DECLARATION identifies the actual handwritten entity, AUGMENTS identifies its actual source type. The source content hash and original declaration span must match the exact requested document. `binaryOrGeneratedEvidence` for this adapter is a closed `java-binary-member:m8.4-v1` payload: `schema`, exact resolution `slot` digest, Java `package`, ordered declaration `owners` (top-level then nested, retaining literal `$` identifiers), `kind` (TYPE/CONSTRUCTOR/METHOD/FIELD), `name`, JVM `descriptor` (empty for TYPE; `<init>` plus a void method descriptor for constructors), and a verified transformation-input `ContentHandle`. Binary names and nested declaration identity are distinct; do not guess owner nesting by splitting a raw `$` name.

Its protected correspondence proof answers `java-source-binary-census:m8.4-v1`: exact `scope`, `slot`, and `members`, where each member is the complete correspondence payload with only `proof` omitted, sorted by canonical JSON. The proof subject is the exact slot digest. This binds the entire per-slot correspondence census without a self-reference. All members require the same expected census answer, current context/policy, endpoint bytes and source bytes. Contrary current answers require explicit adjudication evidence. Metadata/signature alone cannot bypass adapter checks that the selected bytecode class/member census is complete and each SAME_DECLARATION matches the actual source entity. The adapter retains native member provenance as DERIVED, PROJECT, without a fabricated declaration span; handwritten declarations remain DIRECT with original spans. Generic owner/poly-expression and other unestablished attribution cases retain typed provider requirements. Native generator qualification remains separate from authored classfile contract fixtures.

Identity dependency order is acyclic: raw publication/census and upstream native input facts → lineage → separately issued lineage/ownership proofs → output rows/overlay → assembled Java resolution → input view → analysis → occurrence decisions. `nativeResolution` is upstream captured evidence, never the assembled manifest that references the overlay. Root/context proofs target upstream root/model/ownership assertions, not the enclosing overlay/manifest's own digest. Correspondence proofs target immutable endpoint evidence before a correspondence row includes their reference. Pre-analysis projection cannot contain a proof referring to the input view that consumes it. Validate the entire reference DAG; document identity is never its own preimage.

## Proof checks and trusted construction

Each proof has a complete, unique check census. Common required checks are `SCOPE_MATCH`, `INPUT_CLOSURE`, `REFERENCE_INTEGRITY`, `POLICY_CURRENT`, `NO_CONTRADICTION`. Add these per predicate:

| Predicate | Additional required checks |
|---|---|
| `java.output-bytes` | `PUBLICATION_BINDING`, `LOCATOR_VALID`, `CONTENT_HASH_SIZE` |
| `java.generated-lineage` | `TOOL_RECIPE_BINDING`, `OUTPUT_ASSOCIATION`, `GENERATOR_CENSUS_CLOSED`, `OWNERSHIP_PROVEN` |
| `java.resolution-context` | `COMPILER_INPUTS_VALIDATED`, `ORDER_PRESERVED`, `PLATFORM_VALIDATED`, `SOURCE_CENSUS_CLOSED`, `SEARCH_SPACES_CLOSED` |
| `java.binary-shape` | `NON_LOADING_EXTRACTOR`, `CLASS_FORMAT_VALID`, `MEMBER_CENSUS_CLOSED`, `ORIGIN_PROVEN` |
| `java.source-binary-correspondence` | `OWNER_SIGNATURE_MATCH`, `TRANSFORM_LINEAGE`, `MAPPING_CENSUS_CLOSED` |
| `java.semantic-occurrence` | `INPUT_VIEW_MATCH`, `OCCURRENCE_CENSUS`, `TARGET_MAPPING`, `ORIGIN_PROVEN`, `PROVENANCE_VALID` |
| `java.generator-not-applicable` | `GENERATOR_CENSUS_CLOSED`, `APPLICABILITY_PROVEN` |
| `java.build-validation` | `NATIVE_STAGE_VALIDATED`, `TARGET_CENSUS_CLOSED`, `COMPILATION_APPLICABILITY` |
| `java.gap-requirement-binding` | `GAP_QUESTION_MATCH`, `REQUIREMENT_CENSUS_CLOSED`, `MAPPING_VALIDATED` |

Each check records PASS/FAIL/UNKNOWN and evidence. Required FAIL → REJECT; missing/UNKNOWN → INCOMPLETE; all pass permits ACCEPT only through the applicable trusted validator. Unknown extra check names cannot widen the predicate. This catalog is versioned; an unsupported version keeps the requirement pending. For a negative proposition, an empty table only counts when its denominator/applicability is independently proved.

`answer` contains a predicate-specific canonical projection: bytes handle for acquisition; scoped input→output associations for lineage; ordered manifest content for resolution; owner/signature/attributes for binary shape; matched endpoints/method for correspondence; category/occurrence/target/candidates/status/origin/provenance for semantic resolution; closed census and applicability for N/A; target/stage/result for build. Compare these normalized answers, not whole receipts or signature bytes. Different diagnostic packaging is not automatically a semantic conflict; different relevant inputs/answers cannot be normalized away.

The additive `java.gap-requirement-binding` answer is `java-gap-requirement-binding:m8.4-v1` with exact `scope`, original `gap` identity, `gapContent` SHA-256 of the complete original record, and `requirements` sorted by requirement key. Each entry contains `key`, `question`, `subject` and `predicate`. This authenticates the complete mapping, not satisfaction. Raw `gapRefs` are audit/census fields and cannot supply that authority. The existing proof shape already admits a namespaced question/predicate and the record union remains 17 kinds; the registered method/policy must explicitly authorize this additional predicate.

## Lifecycle and reason mapping

PENDING → NARROWED/SATISFIED/NOT_APPLICABLE/CONFLICTED; NARROWED → any evidence-supported state; SATISFIED/NOT_APPLICABLE → REOPENED/CONFLICTED on invalidation; REOPENED/CONFLICTED → a new supported state only with full prerequisite/conflict adjudication. A no-op repeated decision is idempotent. The causal graph, not this transition list alone, establishes the current state.

New catalog `evidence.java-build-closure:m8.4-step4-v1` reuses `capability-gap-record-v1`. Every reason has a detecting observation, requirement, affected output and exact root-cause provenance:

| Reason family | Requirement / handling |
|---|---|
| `PUBLICATION_UNAVAILABLE`, `PUBLICATION_SCOPE_MISMATCH`, `CONTENT_HASH_MISMATCH`, `OUTPUT_CENSUS_OPEN` | Acquisition; preserve raw handle and row, withhold affected import |
| `LINEAGE_SCOPE_UNPROVEN`, `GENERATOR_INPUT_MISSING`, `GENERATOR_TOOL_UNPINNED`, `GENERATOR_CLOSURE_OPEN`, `STALE_GENERATED_OUTPUT` | GENERATED_SOURCE / ISOLATED_BUILD_OUTPUT; obtain native lineage, no stale-directory fallback |
| `OUTPUT_OWNER_UNPROVEN`, `OBSERVED_ROOT_UNVALIDATED`, `OUTPUT_COLLISION`, `SOURCE_SET_ROLE_UNKNOWN` | Build/source-plan evidence; retain all candidates/roles |
| `BINARY_FORMAT_INVALID`, `ARCHIVE_MEMBER_AMBIGUOUS`, `BINARY_VERSION_UNSUPPORTED`, `UNSAFE_OUTPUT_LOCATOR` | BYTECODE/acquisition; preserve entry disposition, use safe compatible reader/worker |
| `CLASSPATH_ORDER_UNPROVEN`, `PLATFORM_VIEW_MISSING`, `JPMS_CONTEXT_UNPROVEN`, `DUPLICATE_CLASS_CONFLICT`, `SEARCH_SPACE_OPEN` | Exact dependency/platform/build context; never append ambient inputs |
| `SOURCE_BINARY_CONFLICT`, `CORRESPONDENCE_UNPROVEN`, `SEMANTIC_MAPPING_UNPROVEN`, `SOURCE_PROVENANCE_MISSING` | Semantic mapping/bytecode/source evidence; preserve candidates, no false resolved fact |
| `VALIDATION_METHOD_UNAVAILABLE`, `VALIDATION_REJECTED`, `EVIDENCE_REVOKED`, `PREREQUISITE_REOPENED` | Typed evidence/policy; active requirement and dependent invalidation |
| `WORKER_CAPACITY_REQUIRED`, `STORAGE_UNAVAILABLE`, `CANCELLED_WITH_FRONTIER` | Resource/recovery; retain checkpoint and all unprocessed obligations |

Do not treat these family labels as a second incompatible global enum. Register exhaustive reason→requirement→affected-output mappings in Phase 2. Unknown reasons are preserved as unsupported catalog records, never silently coerced.

## Validation layers and migration

1. **Wire:** strict decode, schema/version, types/enums, numbers and structural conditionals. JSON Schema cannot detect duplicate raw JSON keys after a permissive parser has discarded them; the codec must reject them first.
2. **Content:** canonical encoding/order, raw paths, hash/size, table rows/counts, source/archive references and source span evidence.
3. **Relations:** exact scope consistency, row-key derivation, ownership, slot contiguity, no dangling refs/cycles, decision supersession and count equations.
4. **Authority:** controller/validator provenance, exact registered checks, policy/revocation, current prerequisite state. No deserialized ACCEPT becomes a trusted object.
5. **Semantics:** native generator fixtures, independent oracle labels and full pipeline controls in the matrix.

Versioned bridges retain legacy raw artifacts. V2 generated bundles may be read as supplied evidence with their original validation scope; no missing native/compiler lineage is filled in from an allowlisted producer. Legacy SATISFIED records enter audit; current closure needs a revalidated matching predicate/scope. Missing applicability/reopening data stays pending. Generic and Core MVP publications have different readers. New unknown schema versions are retained as unsupported records and cannot execute or satisfy anything.

The accompanying [checker](schemas/check_m8_java_evidence.py) performs schema meta-validation, synthetic positive/negative wire examples and local structural assertions only. Its fixtures are illustrative shapes, explicitly **not actual generated/build evidence**. Phase 2 ports the applicable cases into production codec/domain tests and supplies actual CAS/authority/semantic verification.

## Phase-2 adapter payloads (2026-10-21)

The 17-record union above is unchanged. Two explicitly versioned captured payloads supply adapter layout information; neither can issue a protected proof or register a validator.

- `java-generated-root-layout:m8.4-v1` is the canonical answer of a scoped `java.generated-lineage` proof when generated resources are consumed. Its only fields are `schema`, `scope`, and ordered `roots`. Every root has exactly `kind`, `role`, `sourceSet`, `root` (raw `LogicalPath`, or null for the captured work root) and `encoding` (declared charset or null). RESOURCE entries for the selected named set retain native precedence order. A resource must match exactly one role/root by raw path containment; missing/overlapping roots, conflicting order and unavailable original roots withhold assembly. Binary resources retain raw bytes; a text consumer additionally requires an evidenced portable charset. This payload does not turn a resource into generated Java or prove Spring activation.
- `java-class-directory:m8.4-v1` is the canonical captured directory descriptor identified by a CLASS_DIRECTORY slot's `original` handle. Its only fields are `schema`, `scope`, `root` (raw `LogicalPath`, or null for the work root), and `tree` (the exact sealed `java-output-row-table` handle/count also bound by the slot). The adapter strips only this evidenced raw root prefix, verifies every accepted member and preserves resources in a separately hashed deterministic solver JAR. Foreign/outside-root rows, links, open dispositions, duplicate member names or missing content withhold the view. The descriptor/tree and original content hashes remain in the resolution/graph evidence; the derived JAR never replaces them.

`JavaEvidencePreAnalysis` enumerates a minimum context census plus captured output/lineage/binary obligations. The assembler accepts only an opaque reconciler-issued publication and requires its census to cover this footprint; a decoded projection with zero counters cannot substitute for it. This minimum does not yet integrate all readiness/root-discovery obligations. Post-analysis reconciliation is a separate publication described below. Current implementation/acceptance limits are recorded in the [Phase-2 execution record](../tasks/m8/04-step4-phase2-execution.md).

The additive `BinaryInput.NativeOrigin` mapping is separate from M1 `ClasspathEntry`. Its ordered `java-binary-native-origins:m8.4-v1` projection binds solver entries, original native coordinates/hashes, slot IDs, module association and protected context/shape proof IDs into `java.binary-native-origins`. Physical paths are excluded. Metadata alone cannot authorize a frontend request: an opaque capability checks the exact slot census, solver digest, named context, ordinal, cardinality and current referenced evidence. Non-JAR adapted views require an explicitly bound `selectedView`; otherwise the planner withholds correspondence. The original constructors keep the source-only/supplied-artifact lane. Spring origin consumers use a revalidated `FrontendRequest.originClasspath()` overload; their manifest-only constructors retain the original strict membership checks. This is input/provenance support, not qualification of a native semantic provider.

## Captured semantic census adapter (2026-10-22)

The union remains 17 records. `JavaSemanticEvidence` strictly reads the following canonical CAS payloads through generic `java-evidence-input` rows with role `SOURCE` and the exact census provider. An optional generic locator is retained in the row; it is never consulted as semantic origin or a host path. These payloads describe captured observations; they cannot register a provider, qualify a compiler/indexer or mint a protected proof.

| Payload schema | Exact fields beyond `schema` |
|---|---|
| `java-semantic-census:m8.4-v1` | `scope`, `inputView`, `analysis`, `provider` (`id`, `version`), `documents` (input-table descriptor), `proof` (proof digest or null) |
| `java-semantic-document:m8.4-v1` | `document` (M1 source identity), `content` (original bytes handle), `disposition` (`CLOSED`, `PARTIAL`, `OPAQUE`), `categories` (every currently registered `java.*` category and its nonnegative occurrence count), `occurrences` (input-table descriptor) |
| `java-semantic-occurrence:m8.4-v1` | `inputView`, `analysis`, `document`, `category`, `span` (full M1 span or null), `caller` (canonical M1 Entity handle or null), `targets` (distinct canonical M1 Entity handles), `status` (M1 SemanticStatus), `proof` (digest or null) |

The document table must equal the exact requested source census, including documents with zero occurrences. Per-category counts must equal the captured occurrence rows; all registered categories (currently 18) are explicit. A complete disposition and a different provider ID are necessary checks, not evidence of provider independence. A separately qualified validator must establish the independent traversal and closed denominator through the protected `java.semantic-occurrence` predicate/checks. No provider-emitted empty table closes its own denominator.

`RESOLVED` requires one target, caller and full span. `AMBIGUOUS` requires at least two targets; `UNRESOLVED`, `UNSUPPORTED` and `ERROR` have no asserted targets. The importer preserves these obligations but currently closes only an exact resolved frontend mapping with VERIFIED origin/provenance, matching caller and target Entity content. It rejects duplicate `(document, category, span)` locations rather than choosing a winner; providers requiring multiple facts at one location need an explicit richer mapping and remain unsupported here. Reactor-resolution documents and multiple frontend requests are not yet supported by this bounded adapter. There is no compiler-attribution fallback or native indexer execution in this importer.

The location subject is the SHA-256 of `{schema: java-semantic-location:m8.4-v1, scope, inputView, analysis, document, category, span}`. The whole-census subject uses `{schema: java-semantic-census-key:m8.4-v1, scope, inputView, analysis}`. Each proof answer is the canonical corresponding captured payload with only `proof` removed. Exact scope, view, analysis, named source set, policy, predicate and current CAS are required. The whole-census requirement is a prerequisite of every occurrence requirement; unexpected frontend locations add obligations and keep the denominator open. Discovered contrary valid proofs remain conflicts even if omitted from the selected answer.

The separate reconciler publication binds `{schema: java-post-analysis-census:m8.4-v1, scope, inputView, analysis, frontendResult, captured, requirements}`, where `frontendResult` hashes the exact complete FrontendResult, `captured` is the captured census handle, and `requirements` are sorted requirement keys. It uses the existing closure ledger/projection schemas without feeding the result back into the pre-analysis view. An optional prior opaque publication preserves every decision and requires the same census/requirements; changed results or captures require a new ledger. Missing/revoked evidence reopens prior satisfaction, and recovery requires current proof plus explicit causal supersession. Historical current views remain immutable.
