## Responsibilities and trust

The platform-owned `polyglot/architecture/worker.cjs` receives an explicit captured context and immutable source/resolution bytes. Real compilers/parsers produce native structural/binding observations. Target JS modules, package scripts, configuration plugins, browser applications, database connections and deployment commands are never invoked. Target analysis runs through the registered isolated executor; host tests use fixed platform-authored fixtures only.

The neutral `ArchitectureCapture` reader runs no tools. It revalidates raw capture identity, expected scope, selected profiles/configuration, independently supplied source handles, complete document dispositions, fact populations bound to independently admitted source roles, the F01–F12 document census, original UTF-16/line-column positions, conditions, uncertain-fact gaps and derived bytes. Native Vue program links must name existing, same-source virtual/mapping artifacts of the correct kind; wrapper footprints must address captured source and valid original coordinates. CAS tables and `ArchitectureCaptureQuery` provide bounded continuations. A cursor binds the exact result, section and filter; empty filtered pages retain the underlying continuation.

SFC module references can reuse an exact same-source native `MODULE_REFERENCE` observation, rather than reporting an already resolved package as a missing resource. The reader checks the supporting observation ID, kind, target, path and quote-adjusted original span. Missing/ambiguous native evidence keeps the scoped fallback; no contradictory evidence is overwritten.

A stopped worker's semantic bytes may be reconstructed for a fixed authored fixture only when a real-SDK replay matches the VM-reported SHA-256 and length exactly. This is content-identity recovery, not a successful export or host target-execution lane. Full output-census verification remains a separate unchanged gate; an interrupted census stays incomplete. Frozen producer code and original inputs identify the recovered revision.

All output remains **PRODUCER_ASSERTION / qualified=false**. Valid hashes/native exits prove neither semantic accuracy nor production validation-method qualification. `ARCHITECTURE_METHOD_UNQUALIFIED` remains explicit. The document census does **not** establish per-occurrence completeness. `ArchitectureCaptureAudit` additionally evaluates independent caller-supplied source handles, half-open source windows (the observed span must be contained), category/kind, target, attribute and status predicates, and explicit count bounds. Its immutable expectation/disposition tables retain SATISFIED, OMITTED, UNCERTAIN, MISMATCH, AMBIGUOUS and FORBIDDEN outcomes; non-satisfied rows emit typed gaps. `ArchitectureCaptureQuery.occurrences` binds continuation to the audit and filters. Reordering expectations replays identically; empty or source-forged denominators reject. These are selected predicates, never an emitter-defined universe or a production accuracy certificate. This lane has no score or complete-root promotion.

Original HTML, Vue, Svelte and Astro script excerpts also enter the real TS checker. Each component excerpt has a separate lexical context; unrelated component scripts cannot lend wrappers to each other. The primary TS/Angular program is restored after these checks. `source-excerpt:m8.4-v1` records language, original UTF-16 range and SHA-256; the core reader rechecks those bytes against the captured parent. Excerpt checking is explicitly partial (`EMBEDDED_LANGUAGE_CONTEXT_PARTIAL`). With the full native Vue program admitted, excerpt-only diagnostics are not promoted to target type errors; real mapped SFC diagnostics remain. Architecture binding traversal still exposes `EMBEDDED_BINDING_CONTEXT_PARTIAL`. This does not claim complete Svelte/Astro language-service validation. Macros, composition of multiple script blocks, document script order and non-default HTML script bases retain obligations.

React element-returning factories and actual React base classes have native declarations. `CALLABLE_OWNER` joins the enclosing callable, its compiler symbol, class container and parent scope to state/API observations. Namespace JSX uses compiler intrinsic-name rules and checks type-only namespace prefixes. Binding a dynamic property does not establish the implementation component. Next execution directives require a directive prologue and a valid selected tuple; conflicting module directives and function server-action validation stay explicit.

PostCSS and CSSTree parse standalone and embedded CSS from original native HTML/SFC locations. Native URL tokens preserve repeated/escaped occurrences; generated Svelte CSS/maps are separate helper artifacts. HTML references use the declared document base within the captured source URI namespace; external bases do not become local-file edges. Native coordinate indexing preserves BOM/CRLF and rejects surrogate splits. Whole-document supporting spans carry `DOCUMENT_SUPPORT`, so they cannot be advertised as exact declaration locations.

Resolved framework APIs follow compiler symbols and captured package metadata, rather than a spelling such as `useState` or `get`. Pure local API wrappers are followed through resolved declarations, bounded substitution and a visited set. Wrapper footprint and endpoint uncertainty remain visible. Unregistered profile tuples retain generic results and explicit profile obligations.

The optional pinned route SDK provides native file models through Next 15.5.28 collection/mapping, Nuxt's `unrouting` 0.3.1 tree engine, SvelteKit 2.37.1 manifest-data generation and React Router 7.9.4 file/declaration helpers. Captured configuration is parsed as TypeScript syntax: immutable literal data/aliases and explicitly imported native Router helpers are projected; target modules/functions are not executed. Next's native schema and source-root discovery and Kit's native configuration validator qualify supported paths/options. Relative paths must stay inside captured roots before native filesystem scans. Opaque/mutated/import-effectful configuration is partial. Config support/hash, effective-config status, native hierarchy and parameters stay with each conditional route; file discovery never certifies runtime reachability. One registered guest checkpoint establishes the scoped new native paths, not all effective configurations or deployed worlds.

Module Federation profiles use the pinned Next-bundled Webpack 5.98.0 constructor to validate literal options without applying the plugin or compiling targets. Exposes bind captured files; imported remotes/shared dependencies remain declared/conditional, with hashed requests and unknown deployed content/instances. Unsupported normalized forms retain scoped obligations. Native records point to actual captured documents, not synthetic directory paths.

## Schemas, configuration and resources

The current adapters cover JSON/JSONC, YAML, TOML, properties/env keys, Protobuf source declarations, GraphQL schemas/operations/fragments, configured SQL dialects, namespace-aware XML, HCL declarations, Docker directives, shell command declarations, CSS imports/layers/custom properties and captured resource references. OpenAPI operation identities include app/document ownership. JSON Schema references use captured resources/base URIs/fragments/anchors; no embedded URL is fetched. Duplicate keys, unavailable/cyclic references, unsupported versions, XML entities, missing SQL dialect/search path and native failures retain gaps and healthy siblings.

Compose/Kubernetes/workflow/AsyncAPI data has declared structural projections, not deployment or universal dialect certificates. Avro records are additionally checked by the pinned avsc schema engine. Explicit captured GraphQL schema/fragment contexts support anonymous operations, native schema validation and field references with the actual schema/fragment source. OpenAPI parameter inheritance, bodies, responses and media types retain source ownership. Duplicate schema base URIs retain ambiguity; missing context and unsupported dialects remain gaps. Literal config/credential values and endpoint strings are excluded from public facts apart from structural identities such as routes, namespaces and manifest names; public server/remote/range values use keys or digests. Test/generated/vendor/resolution populations stay separate from authored production inputs.

`context.protobufDescriptorSets` explicitly selects binary FileDescriptorSet inputs. Native protobufjs decode/fromDescriptor records packages, imports, messages/fields/enums/services/methods and actual/supported declaration counts. Binary transport is canonical base64 with exact original byte hashes, never UTF-8 coercion; binary facts have no invented source span. Unsupported/incomplete metadata retains a specific gap rather than a redundant generic missing-provider gap. Native SQL AST DDL supplies table/view/column/key declarations; version/namespace-scoped persistence XML supplies declared ORM mappings. `context.sqlMigrationProfiles` registers `flyway-default-sql:1` roots for numeric default naming/order and duplicate-version conflicts. These are source declarations, not database history, physical naming defaults or executed migration results.

Properties preserve escaped separators/Unicode, logical-line continuations and the final assignment within that document; values remain private. Captured package manifests own files and conditional export alternatives; declared dependency ranges do not imply a resolved package-manager closure. `context.templateProfiles` can register `{id:'thymeleaf-html-literals',version:'3.1',roots:[...]}`: existing parse5 positions bind literal `.html` template/fragment declarations and `th:insert`/`th:replace` (including `data-th-*`). Roots are explicit captured namespaces. Dynamic selectors/parameters, duplicate targets, custom resolver behavior and include cycles retain obligations; the profile does not render templates or execute expressions. Other template/build/binary dialects retain their dispositions/provider obligations. The [Thymeleaf fragment contract](https://www.thymeleaf.org/doc/tutorials/3.1/usingthymeleaf.html#template-layout) defines the source syntax; parser success is not engine validation.

`context.sourceMaps` selects captured generated/map pairs. Native trace-mapping validates map version, captured sourcesContent hashes, UTF-16 coordinates, unmapped segments and hash-linked transform chains. Generated Vue/Svelte/Astro artifacts/maps stay separately addressed. Vue render-map coordinates refer to the exact HTML template excerpt, whose offset/hash is revalidated against its SFC and again by the Java reader; they are not whole-file coordinates. Empty/forged/unavailable maps keep gaps, including legitimate empty Svelte compiler maps. Mapping precision and semantic accuracy remain separate. Invalid TS/Angular context options withhold the affected checker rather than losing independent schema/resources; unsafe plugins/emit options are still not executed.

`nativeNuxtConfig:true`, an explicit production/development mode and a captured `routeModels` config enable pinned @nuxt/schema 4.6.3 / untyped 2.0.0 defaults. The SDK resolves statically captured data in a separate Node permission process with a clean environment and reads restricted to the pinned SDK, controls and captured namespace. Source roots, pages directory and base URL are checked before native route emission. Target config/modules/hooks are never evaluated; effects, layers, escaping roots and uncaptured environment defaults remain obligations. This projection is native schema validation, not a full Nuxt application build. Vue options are restricted to registered booleans; target plugins are never loaded. Native virtual documents are disposed per analysis, and helpers remain generated artifacts.

## Identity, bounds and replay

`architecture-request:m8.4-v1` binds repository/app, exact context, selected profiles and captured files. Input closure also binds every path/hash/size/population. The source scope is distinct from tool identity. Logical architecture identifiers exclude provider versions; capture identity includes tool/extractor bytes, native artifacts, facts, gaps and the census. Context conditions stay attached to each fact; source-declared guards do not establish one universal runtime world.

`architecture-capture:m8.4-v1` remains readable as the original no-artifact prototype. V2 adds independently hash-checked generated bytes and source-map artifacts. Old captured outputs are not rewritten or requalified. Tool pinning binds the exact npm lock, installed runtime tree, platform/runtime tuple and extractor modules. Additional Nuxt/Vue pins are small descriptors over existing external SDK trees; they do not copy dependencies into Git. SDK archives require a `package/` envelope and registered expansion profiles. The checked-in lock supports `npm ci --ignore-scripts` into an explicit tool directory; application dependencies still belong in captured contexts, not ambient module resolution.

The JS worker admits one bounded 64-MiB source context; the authored campaign transport is separately bounded at 64 MiB. These are worker/transport limits, not repository eligibility limits. Repository orchestration must partition or escalate resource classes and retain continuations. Core JSON/row/query budgets are explicit, with cancellation and failure rather than silent denominator shrinkage. Whole-repository graph/product integration remains the existing Bước 3/Step 6 responsibility.

## Native API references

The implementation uses the [Vue compiler-sfc pipeline](https://github.com/vuejs/core/blob/main/packages/compiler-sfc/README.md), [Angular AOT/template checking](https://angular.dev/tools/cli/aot-compiler), [strict-template modes](https://angular.dev/tools/cli/template-typecheck), [Svelte compiler](https://svelte.dev/docs/svelte/svelte-compiler) and [Astro compiler API](https://github.com/withastro/compiler). The Astro project documents incomplete position data; this adapter validates source slices and withholds unsupported mappings. Native API availability and these references are separate from the finite acceptance evidence.

CSSTree location/token behavior follows its pinned [AST contract](https://github.com/csstree/csstree/blob/v3.1.0/docs/ast.md) and [parser options](https://github.com/csstree/csstree/blob/v3.1.0/docs/parsing.md). Directive and fragment controls also follow the [Next directive contract](https://nextjs.org/docs/app/api-reference/directives/use-client) and [GraphQL fragment target rules](https://spec.graphql.org/September2025/#sec-Fragment-Spread-Target-Defined). These references are API/specification evidence, not qualification results.
