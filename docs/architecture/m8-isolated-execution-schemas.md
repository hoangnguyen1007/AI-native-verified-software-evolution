# M8.4.3 — Typed execution record catalog

Date: **2026-10-19**. **PROVISIONAL / Phase-1 specification, not production serialization.** The [execution contract](m8-isolated-execution.md) owns semantics and algorithms. This catalog owns field types, identity boundaries and validators. The [JSON Schema](schemas/m8-execution-plan-v1.schema.json) covers `ExecutionPlan`, `ExecutionTask`, `ExecutionEdge` and `RequirementBinding`; remaining records below are typed designs for Phase-2 Java records/codecs, not a claim that machine schemas/parsers already exist for them.

## Common wire rules

- `Digest` = lowercase `sha256:` plus 64 hex digits. `Handle` = `{digest: Digest, size: U64}` with size limited to Java nonnegative `long` (0..9223372036854775807); offsets/counts use the same checked range. Overflow is invalid, never wraparound. Counts are serialized as JSON integers; JS consumers must use lossless parsing/string projections above 2^53-1. Do not use binary floats.
- `Id` = nonempty exact string scoped to its owning record/plan. `Version` = `{id: Id, version: Id}`. Enums are closed and case-sensitive. Unknown schema/enum is a typed unsupported-version outcome; do not guess a default. Exact Unicode scalar strings, no implicit normalization; reject invalid surrogate/encoding sequences.
- `Set<T>` means distinct canonical sorted array, not unspecified iteration. `Seq<T>` preserves order and repeats. `Map<Id,T>` sorts keys using existing canonical UTF-16 ordering. Nullable fields are explicitly marked `?`; absence is rejected for required fields, and null never means an empty collection.
- `LogicalPath` reuses `{rawBase64: string}` and its raw-byte validation/comparison. `GuestLocation` = `{mount: SOURCE | WORK | TOOLS | MATERIALS | OUTPUT, relative: LogicalPath?}`; null relative denotes that mount root. No absolute host path is a domain input. Guest mount locations and executable resolution are controller-owned mappings with their own digest.
- `ScopedRef` = `{plan: Digest, localId: Id}`. `ContextRef` = `{context: Digest, reference: ScopedRef}`; `context` must equal the referenced context record's digest, not a module name alone. `EvidenceRef` = `{artifact: Handle, recordKey: Id?, provider: Version}`; selector resolves deterministically into the verified artifact.
- Every persisted top-level record requires a schema string with its own version; the record digest is computed externally as `SHA256(CanonicalJson(record))`. No record contains its own digest. Tables below omit the repeated `schema` field. Referenced records have to exist, hash correctly and match their expected kind/version.
- Large collections are `TableRef<T>` = `{schema: Id, content: Handle, rows: U64}`: a streamed canonical NDJSON table of T records, UTF-8, one canonical record plus LF per row, no header/BOM. Hash the exact table bytes; count all rows. Table schema fixes key/order; duplicate keys with different data are invalid. Table order for tasks is external task digest; for edges `(predecessor,consumer)`; for requirement bindings `ScopedRef.localId`. Disk segments/indexes are derivatives; repartitioning preserves logical table bytes/digest. Paging cursors bind table digest, row key and schema, not a mutable offset alone.
- Input/output/material **contents** are raw-byte handles; do not normalize archive timestamps, line endings or generated bytes. Redacted display data is a different artifact with a policy reference. Protected raw data is never returned automatically by bounded APIs.

| `AcceptanceCandidate` (embedded) | `task: Digest`, `outputRole: Id`, `predicate: Version`, `evidenceRole: Id` | Predicate is from the registered catalog, not arbitrary executable expression. | `LoweredRecipe` / `execution-recipe:m8.4-v1` | `sourceRecipe: ScopedRef`, `adapter: Version`, `family: Id`, `scope: ROOT \| PROVEN_GROUP`, `footprint: Digest?`, `contexts: Set<ContextRef>`, `commands: Seq<CommandSpec>`, `inputManifest: Handle`, `expectedOutputs: TableRef<OutputExpectation>`, `toolPins: TableRef<ToolPin>`, `environment: Digest`, `network: Digest`, `resources: Digest`, `sideEffects: Set<Id>`, `predicates: Set<Version>` | Default ROOT. | `CommandSpec` (embedded) | `tool: Digest`, `argv: Seq<String>`, `cwd: GuestLocation`, `environment: Digest`, `phase: Id`, `targetSelector: Handle`, `continuation: STOP_ON_FAILURE \| NATIVE_CONTINUE` | No shell interpolation. Registered native wrapper/script execution may use a pinned interpreter with script handle as argument **in guest only**. Host invocation is only driver/control code; no target command flag forwarding |
| `ToolPin` / `execution-tool:m8.4-v1` | `role: Id`, `provider: Version`, `binary: Handle`, `distribution: Handle?`, `platform: Digest`, `acquisition: EvidenceRef`, `licenseDisposition: Id` | Bind compiler/build/indexer/capture helper/wrapper distribution separately. Version label or descriptor hash alone does not pin executable bytes |
| `OutputExpectation` / `execution-output-expectation:m8.4-v1` | `role: Id`, `contexts: Set<ContextRef>`, `location: GuestLocation`, `category: Id`, `presence: REQUIRED \| OPTIONAL \| NATIVE_DISCOVERED`, `predicate: Version` | OPTIONAL absence does not imply satisfaction of unrelated requirements. Native-discovered roots require provenance; no speculative wildcard can prove a closed output census |

An `ExecutionTask.inputs` set is sorted by role, then tagged binding preimage. The task must still reject duplicate roles even if JSON objects differ. Context/task/requirement references are plan-qualified at use; a digest from another plan cannot silently alias. The JSON schema checks shapes only; Phase-2 validators implement these relations.

Acceptance candidates sort by `(evidenceRole, task, outputRole, predicate.id, predicate.version)`. ANY_EQUIVALENT requires exactly one distinct evidence role. ALL_OF groups candidates by role and requires an accepted equivalent proof in every group; multiple alternatives per role are allowed. A rejected/unavailable alternative is not automatically a contradiction; a differing substantive observation triggers explicit conflict. Registered applicable producers must all have dispositions before canonical finalization. Thus `(A or B) and C` has two roles and three candidates without a new schema or hidden first-finish preference.

Security configuration records may be access-controlled; their digests can be exposed without secret values. `Instant` uses normalized UTC ISO-8601 in operational records only. Conformance/trust-policy validity at reuse time is an operational admission check; immutable past evidence remains unchanged when a qualification expires.

References such as transport, DNS/TLS, disclosure, progress, retention and retry policies identify operator-owned registered configuration, never a guest-supplied free-form document. Adapter-specific fields require their own declared schema and codec in Phase 2. A missing policy schema/implementation is an unsupported-provider requirement, not permission to ignore the policy. Native tool versions and backend-specific settings are pinned at implementation/qualification, not invented by this design.

`FootprintProof` (`execution-footprint:m8.4-v1`) contains `readiness: Digest`, `adapter: Version`, `nativeTool: Digest`, `contexts: Set<ContextRef>`, `readSet: Handle`, `writeSet: Handle`, `sharedEffects: Handle`, `coCompilation: Boolean`, `validation: Digest`. The sets identify exact path/material scopes and known external effects. A claimed footprint from the target alone is not a proof; `validation` must establish independence and legal native grouping. Unknown/global effects force ROOT scope.

`DiscoveryDelta` (`execution-discovery:m8.4-v1`) contains `parentPlan: Digest`, `provider: Version`, `observation: Digest`, `addedRoots: Handle`, `addedContexts: Handle`, `addedRequirements: Handle`, `relations: Handle`, `conflicts: Handle`, `selectionPolicy: Digest`, `frontier: Handle`. Each handle is a typed table in the provider's registered discovery codec. Delta does not issue commands. Native disagreement with a passive candidate retains a correspondence/conflict and original candidate; it does not silently delete it. Replanning consumes the delta only after validation.

## Required semantic validation beyond JSON Schema

1. Verify all handles, schemas and reference types, canonical ordering and absence of duplicate semantic keys. Reject unresolved graph endpoints/slot roles, foreign contexts and unknown predicate versions.
2. Verify DAG acyclicity, exact requirement coverage, SCC/footprint qualification, candidate expression semantics and native grouping legality.
3. Verify sandbox qualification against underlying descriptors, controller trust root, current revocation policy, fencing, receipt authenticity, material/output closure and per-category promotion checks.
4. Verify publication order and atomic revision, root/selected-context/source-set denominator, active conflict/revocation handling and zero-output applicability proof.
